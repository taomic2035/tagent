## 0.1 什么是 Agent

**定义**：agent（智能体）是能让大语言模型（LLM）**自主决定并执行动作**的程序。
它和聊天机器人的区别不在"会说话"，而在"会动手"：

- 聊天机器人：你问"北京多少度？"，它只能编（或用训练时背下的旧数据）回答你
- agent：模型发现回答需要实时数据 → **主动发起一次工具调用**（查天气的函数）→
  拿到结果 → 组织成回答。整个"发现→调用→整合"的决策由模型自己做

用一句话记住全书的主题：**agent = LLM + 工具 + 一个循环**。循环把"模型想干活"
变成"活真的被干了"。这个循环我们在第 3 章亲手写，只有二十几行，但它是全部。

> 术语出处：本文所用 tool calling / function calling 等概念均以 OpenAI
> Chat Completions API 规范为准（platform.openai.com/docs/api-reference/chat），
> 这是事实上的行业标准，也是我们本地引擎兼容的对象。

## 0.2 全景图：你的电脑上将跑着三个东西

全书只讲一个架构，先看图（记不住没关系，每章都会回顾）：

```
┌─────────────┐   HTTP + JSON（OpenAI 兼容协议）   ┌──────────────────┐
│   壳（Shell） │ ─────────────────────────────────► │   大脑（Core）     │
│  你打字的地方  │                                    │  agent 循环+工具   │
└─────────────┘                                    └────────┬─────────┘
                                                            │ HTTP + JSON
                                                            ▼
                                                   ┌──────────────────┐
                                                   │  引擎（Engine）    │
                                                   │  llama.cpp + 模型  │
                                                   └──────────────────┘
```

三件套的职责边界（全书不变量）：

| 部件 | 职责 | 本书对应 | 绝不做的事 |
|---|---|---|---|
| **引擎** | 跑模型推理，吐 token | llama.cpp server（第 1 章） | 不懂你的业务、不联网查资料 |
| **大脑** | agent 循环：请求模型→解析工具调用→执行工具→回填结果 | packages/core（第 2-4 章） | 不直接渲染 UI、不依赖任何框架 |
| **壳** | 人机界面：收你的字、流式渲染回复 | apps/cli（第 2 章） | 不做任何决策逻辑 |

**为什么这样分**：大脑零依赖（只用 zod）且不感知壳的存在，所以同一份大脑
以后可以直接接到手机壳、网页壳——这是本教程第 8 章移动端大作业的全部前提。
业界叫法：分层架构（layered architecture）+ 依赖注入（dependency injection，
第 2 章你会看到它的最小形态）。

三件之间说的是同一种话：**HTTP 上的 JSON**，遵循 OpenAI Chat Completions 协议。
"OpenAI 兼容"意味着：你为本地引擎写的代码，改个地址就能调云端 API（反之亦然）。

## 0.3 术语与规范索引

全书术语在此一次性给出。**不要现在背**——每次遇到新术语回这查，定义都带权威出处。

### 通信与数据格式

| 术语 | 定义 | 出处 |
|---|---|---|
| **HTTP** | 应用层协议，客户端发"请求"（方法+地址+头+体），服务端回"响应"（状态码+头+体） | MDN HTTP 文档 |
| **API** | 应用编程接口。本书特指"HTTP API"：约定好请求/响应格式的远程调用 | — |
| **JSON** | 文本数据格式，`{"键": "值"}`。模型间传输的一切结构化数据都是它 | json.org |
| **SSE**（Server-Sent Events） | 服务器单向持续推送的 HTTP 长连接流，`Content-Type: text/event-stream`，每帧以 `data:` 前缀、空行分隔 | MDN Server-sent events；我们第 2 章手写解析 |
| **请求体 / 响应体** | HTTP 消息的正文（JSON 字节） | — |

### 模型与推理

| 术语 | 定义 | 出处 |
|---|---|---|
| **LLM**（大语言模型） | 以 token 为单位生成文本的神经网络 | — |
| **token** | 模型处理文本的最小单位。中文约 1 字 = 1 token，英文约 4 字符 = 1 token（近似值，第 5 章我们写估算器） | OpenAI token 文档 |
| **prompt** | 发给模型的输入（含历史消息、工具说明书） | — |
| **上下文 / 上下文窗口** | 模型一次能"看见"的全部 token 上限。超了就要裁剪（第 5 章主题） | — |
| **推理（inference）** | 模型生成 token 的计算过程。"推理引擎"=跑这个计算的程序 | — |
| **量化（quantization）** | 把模型权重从 16bit 压到 4bit 等，体积/速度大降、能力略降。文件格式 GGUF | llama.cpp 文档 |
| **KV cache** | 引擎对已处理 prompt 的缓存：请求前缀不变则不重算，长对话提速的关键。第 5 章实测 | llama.cpp 文档 |
| **temperature** | 采样随机性参数：0 = 几乎确定（适合测试），越大越发散 | OpenAI 规范 |

### 协议关键字段（本书的主角）

| 术语 | 定义 | 出处 |
|---|---|---|
| **messages** | 对话历史数组，每条 `{role, content}`。role ∈ system / user / assistant / tool | OpenAI 规范 |
| **tool_calls** | assistant 消息里的字段：模型举手"我要调这个工具"，含工具名与参数 | OpenAI 规范 §function calling |
| **tool_call_id** | 每次调用的唯一 id。工具结果消息（role:tool）必须带同值 id 回填，**配对不能拆** | OpenAI 规范；第 3 章的不变量 |
| **JSON Schema** | 描述 JSON 结构的标准（类型/必填/枚举…）。工具的"说明书"用它写，模型照着生成参数 | json-schema.org |
| **finish_reason** | 模型停止的原因：`stop`（说完）/ `tool_calls`（要调工具）/ `length`（token 上限截断） | OpenAI 规范；第 4 章靠它分流 |
| **usage** | 响应里的 token 统计：prompt_tokens / completion_tokens | OpenAI 规范 |
| **reasoning_content** | 思考模式字段：模型出答案前的推理文本（Qwen 系命名；另有引擎叫 reasoning——第 6 章做双认兼容） | 各引擎扩展 |

### 工程术语

| 术语 | 定义 |
|---|---|
| **TDD / 测试先行** | 先写"期望行为"的测试（此时必然失败），再写实现让它通过 |
| **报文存证** | 把每次请求/响应的原始字节落盘归档，事后可追溯、可复现 |
| **故障注入** | 故意把系统某环节搞坏，验证兜底真的兜得住 |
| **降级** | 高级路径走不通时退到保守路径（如"禁用工具逼模型直接回答"） |

## 0.4 命令行最低配置知识

不管你用 Windows Terminal / PowerShell / Git Bash 还是 Mac 的 Terminal，
这五个概念是全书的地基。每个五分钟，现在过一遍，后面全部要用：

**1. 目录与路径**
```
cd D:\LLM        # 进入 D 盘 LLM 目录（Windows 反斜杠；Mac/Linux 是 cd /tmp）
cd ..            # 回上级
pwd              # 我现在在哪（PowerShell 里也通用）
```
> ⚠️ 全书第一个坑：**Windows 路径里的反斜杠 `\` 在 JSON 与多种 shell 里是转义字符**，
> 多层传递时会被吞（`D:\LLM` 变成 `D:LLM`）。本教程约定：**凡是写进 JSON 或代码里的
> Windows 路径，一律用正斜杠 `D:/LLM`**——Windows 自己也认。这是参考实现踩了三天坑
> 换来的纪律，后面每章遇到都会再提醒。

**2. 环境变量**
```
# PowerShell（临时）
$env:TAGENT_MODEL = "D:/LLM/models/qwen.gguf"
# Git Bash / Mac
export TAGENT_MODEL=/path/to/model.gguf
echo $env:TAGENT_MODEL   # 或 echo $TAGENT_MODEL，查看
```
程序从环境变量读配置，命令行就不用每次敲一长串参数。

**3. 管道与重定向**
```
curl -s http://127.0.0.1:8081/health       # 输出直接打印
curl -s http://... > resp.json             # 存进文件
type resp.json        # Windows 看内容（Mac: cat resp.json）
```

**4. 退出码（exit code）**
每条命令结束都带回一个数字：0 = 成功，非 0 = 失败。
```
curl -s http://127.0.0.1:9999/health; echo "exit=$?"
# 输出 exit=7（连接被拒）——报错要看退出码，不要只看有没有输出
```
> 这是工程纪律 6 的技术基础：**脚本判断成败永远查退出码**，"看起来输出正常"
> 不等于成功（第 4 章有真实翻车案例）。

**5. 进程与端口**
```
netstat -ano | findstr 8081    # 谁在监听 8081（Mac: lsof -i :8081）
taskkill /PID 1234 /F          # 杀进程（Mac: kill 1234）
```
引擎就是一个占着端口（本教程固定 8081）的进程。"端口被占用"是新手最常见报错。

## 0.5 慢的预期：CPU 推理的真实速度

本教程全程 CPU（不需要显卡）。先给你真实数字建立预期（参考实现实测，Qwen3.5-4B，
20 核 CPU）：

| 操作 | 速度量级 |
|---|---|
| 模型加载进内存 | 约 3 秒 |
| 生成速度 | 约 12 token/秒 —— 一句 50 字的中文回答约 4~5 秒 |
| 开思考模式后 | 可能 3~10 倍变慢且不一定更好（第 6 章实证） |

慢是特性不是缺陷：它逼我们写出**对每一步都精打细算**的 agent（少一轮循环、
省一个 token 都是真实收益），这正是本教程比"调云端 API"教程多学到的东西。
