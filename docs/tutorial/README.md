# 从零手搓本地 Agent · 教程

> 这不是一本"讲讲 agent 概念"的书。这是一份**构建日志**：跟着它从头敲到尾，
> 你会亲手搓出一个跑在自己电脑上、能查数据、会算数、打不死的真 agent——
> 以及一整套让你确信"它真的在工作"的证据制度。

## 本教程怎么教（组织原则）

1. **按版本里程碑组织**：agent 的能力一次只长一点。v0.1 只会说一句话，
   v0.4 第一次自己调工具，v0.12 通过全部大考。**每个版本结束，项目都能跑**——
   你随时停下来，手里都是一个完整的东西
2. **抽丝剥茧**：每个机制都从最笨的做法开始，**亲手撞墙**（贴崩溃现场原文），
   分析根因，再推导出正确做法。正确答案不是宣布的，是被墙撞出来的
3. **代码完整**：每个版本的每个文件给全量代码，照抄能跑。省略号是概览书的病，
   本书没有
4. **每个决定都有取舍**：为什么这样不那样，失败的方案死在哪，全部记录
5. **真机数据**：所有数字（速度/成功率/命中率）来自实测，报错贴原文

## 读者假设与平台

- 会开机复制粘贴，**愿意学命令行**（第 0 章带你过门槛，不绕）
- 不需要会编程、不需要懂 AI、不需要显卡（全程 CPU 实证）
- **Windows 主线**（每条命令可复制），Mac 附注；代码只用跨平台 API，
  方法不绑定平台

## 工程纪律（贯穿全书，每章自测清单都含）

1. 不引框架不引 SDK：SSE、JSON Schema、循环全部手写
2. 大脑零依赖（仅 zod）：一份代码从终端跑到手机
3. 每次与模型的通信必须存证（请求+响应原文落盘）
4. 功能先写测试（测试是行为的精确定义）
5. 每个功能亲眼看过它失败的样子，才算做过
6. 结论要有证据，成败看退出码

## 本教程的代码经过验证（两轮，正式版）

**第一轮**（拼合验证）：10 项测试全绿，抓出 5 处编译级缺陷（tsconfig
rootDir 解析 / 类型迁移 / ChatRequest.tools / Tool 接口 ctx 演进 / 测试笔误）。

**第二轮**（正式复验）：从修正后的教程**逐字提取**代码块重建独立工作区，
三关全过——①编译零错误（core + cli 全量装配）；②7 项单元测试全绿；
③**真机端到端**三类场景实证：

| 场景 | 结果 |
|---|---|
| 北京天气 | ⚙ get_weather(北京) → 真实数据 → 正确终答 |
| 火星 | 不编造，如实说明工具边界 |
| 故障注入 flaky | 信封兜住 → 模型转向如实告知 |

第二轮又抓出 **13 处**缺陷并全部回填：编译级 6 处（stream 段独立类骨架、
超时测试隐式 any、faults 的 args:never 逆变、cli 缺 zod、core 缺 main 入口、
index.ts 全书缺失）、**行为级 4 处**（壳缺 system prompt 致 4B 拒调工具
甚至编造数据、tools 序列化静默丢失——编译测试全绿但说明书不进请求、
重试耗尽文案渲染 undefined、ChatRequest.signal 与 ActionParse 等类型演进
未交代）、结构级 3 处（第 3 章壳装配无全量、测试标"见对照"违反零省略、
chapter 2 的 cli 配置缺依赖）。

其中**行为级缺陷只有真机端到端能抓到**——编译绿测试绿 ≠ 工具真的发出去了。
这是全书"亲眼看过它工作"纪律的最后一课。
