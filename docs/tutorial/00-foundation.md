# 第 0 章 地基：Agent 的世界观与全书地图

> 读者假设：你有计算机常识（知道进程/端口/JSON/HTTP 是什么、会用命令行）。
> 本章不教这些。本章回答三个问题：agent 到底是什么、系统长什么样、
> 全书要建到多深。深度的标尺先亮出来：**我们要一直讲到引擎内部**——
> token 如何生成、KV cache 为什么在数学上可复用、tool_calls 在模型眼里
> 根本不是结构化数据而是文本。

## 0.1 Agent 的本质：把"会说话"变成"会干活"

LLM 的原生能力只有一件事：**给定一段文本，预测下一个 token**（token 是模型
处理文本的最小单位，第 1 章深讲）。聊天只是这个能力的包装。agent 的全部秘密
在于一个循环：

```
        ┌──────────────────────────────────────────┐
        │                                          │
        ▼                                          │
   [请求模型] ──模型回答──► [只是文本？] ──是──► [展示给用户，结束]
        │                          │
        │                          否（模型说"我要调工具"）
        ▼                          ▼
   [执行工具] ──结果塞回对话历史───────────────────┘
```

模型不能执行任何东西——它只会**生成文本**。但当文本的格式被约定为
"工具调用"，而循环里有一个**忠实的执行者**把它变成真实动作、再把结果喂回来，
"想"和"做"就接通了。这个循环二十几行（第 3 章），但让它跑得稳、省、可证明，
是整本书。

## 0.2 系统解剖：三个进程，一种协议

```
┌─────────────┐  HTTP + JSON（OpenAI 兼容协议）  ┌──────────────────┐
│   壳（Shell） │ ─────────────────────────────► │   大脑（Core）     │
│  你打字的地方  │                                 │  agent 循环+工具   │
└─────────────┘                                 └────────┬─────────┘
                                                          │ 同一种协议
                                                          ▼
                                                 ┌──────────────────┐
                                                 │  引擎（Engine）    │
                                                 │  llama.cpp + 模型  │
                                                 └──────────────────┘
```

| 部件 | 职责 | 深入到哪（全书纵深） |
|---|---|---|
| 引擎 | 跑模型推理 | **第 1 章是全书最深的一章**：tokenizer、推理两阶段、KV cache 的结构、量化、采样 |
| 大脑 | 循环+工具+上下文管理 | 第 2~4 章：协议字节层、循环不变量、失败对策；第二册：压缩/守卫/并行 |
| 壳 | 人机界面 | 第 2/8 章：事件流消费、移动端 |

两条全书不变的底线：

- **协议是唯一接口**：三件之间只有 HTTP 上的 JSON（OpenAI Chat Completions
  规范）。大脑零依赖（仅 zod）且不感知壳——第 8 章手机壳直接带走大脑，
  一行不改
- **messages 是唯一事实来源**：对话发生过的一切（包括工具调用与结果）
  都记录在 messages 数组里。渲染可以丢、事件可以过期，messages 不撒谎

## 0.3 全书知识地图（"幼儿园到大学"的进度表）

| 层 | 知识 | 章 |
|---|---|---|
| 入门 | agent=LLM+工具+循环；三件套架构 | 本章 |
| 应用 | OpenAI 兼容协议：messages/tool_calls/finish_reason/usage | 1-3 |
| **协议字节层** | SSE 帧结构、HTTP chunk 与帧的两层边界、UTF-8 变长编码、流式分片拼接 | 2 |
| **引擎机制层** | tokenizer 与 BPE、prefill/decode 两阶段、KV cache 的因果结构、量化（Q4_K 块）、采样（logits→softmax→temperature）、chat template 渲染 | 1、3 |
| **模型行为层** | tool_calls 的文本本质、finish_reason 的触发条件、错误消息=下一轮 prompt、思考模式与 token 预算 | 3、4、二册 |
| 工程层 | 错误信封、分类重试、超时与取消语义、触顶降级、故障注入 | 4 |

| 验证层 | 存证/溯源/复现/机器裁决 | 5、二册 |

## 0.4 工程纪律（六条，全书每章自测清单都含）

1. **不引框架不引 SDK**：SSE、JSON Schema、循环手写。框架替你挡掉的恰好是你该学的
2. **大脑零依赖**（仅 zod）：一份代码从终端跑到手机
3. **每次通信必须存证**：请求/响应原文落盘——你的每个结论都要能翻出证据
4. **功能先写测试**：测试是行为的精确定义
5. **每个功能亲眼看过它失败**：才算做过
6. **结论要有证据，成败看退出码**

> **引经据典**｜pi（earendil-works/pi）`packages/ai`/`agent`/`coding-agent`
> 工业级同款分层：协议层（packages/ai）→ 循环层（packages/agent）→ 壳
> （coding-agent），甚至把 llama.cpp 做成独立 provider。分层的回报在第 8 章
> 兑现：换壳不换脑。反面教材也在：hermes-agent 早期主循环写进单个
> `run_agent.py`（约 46 万字符），后花大力气拆包——架构债第一天就别欠。
