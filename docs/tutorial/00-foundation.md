## 0.1 什么是 Agent

**定义**：agent（智能体）是让大语言模型**自主决定并执行动作**的程序。
与聊天机器人的区别不在"会说话"，在"会动手"：

- 聊天机器人：你问"北京多少度？"——它只能编，或背训练时的旧数据
- agent：模型发现需要实时数据 → **主动发起工具调用**（查天气的函数）→
  拿到结果 → 组织成回答。"发现→调用→整合"的每步决策由模型自己做

全书主题一句话：**agent = LLM + 工具 + 一个循环**。循环把"模型想干活"
变成"活真的被干了"。它在第 3 章，只有二十几行——但之前之后的所有章节，
都在让它跑得稳、跑得省、跑得可证明。

> 术语规范：本书的 tool calling / function calling / messages 等概念，
> 以 OpenAI Chat Completions API 规范为准（platform.openai.com/docs/api-reference/chat）。
> 这是事实行业标准，也是本地引擎兼容的对象——你的代码换个地址就能调云端。

## 0.2 全景图：你的电脑上将跑三个东西

```
┌─────────────┐   HTTP + JSON（OpenAI 兼容协议）  ┌──────────────────┐
│   壳（Shell） │ ──────────────────────────────► │   大脑（Core）     │
│  你打字的地方  │                                 │  agent 循环+工具   │
└─────────────┘                                 └────────┬─────────┘
                                                          │ HTTP + JSON
                                                          ▼
                                                 ┌──────────────────┐
                                                 │  引擎（Engine）    │
                                                 │  llama.cpp + 模型  │
                                                 └──────────────────┘
```

| 部件 | 职责 | 本书对应 | 绝不做的事 |
|---|---|---|---|
| **引擎** | 跑模型推理，吐 token | llama.cpp（第 1 章） | 不懂你的业务、不联网查资料 |
| **大脑** | 循环：请求模型→解析工具调用→执行→回填 | packages/core（第 2-4 章） | 不渲染 UI、零依赖（仅 zod） |
| **壳** | 人机界面 | apps/cli（第 2 章） | 不做任何决策 |

三件之间说同一种话：HTTP 上的 JSON。**"OpenAI 兼容"是本章最重要的词**——
它意味着第 8 章把壳换成手机、第 9 章把大脑接到任何新壳，大脑和引擎一行不改。

> **引经据典**｜pi（earendil-works/pi）`packages/agent` + `packages/ai`
> 工业级 agent 工具箱 pi 就是这个分层的放大版：`packages/ai`（统一 LLM 协议层）、
> `packages/agent`（无状态循环 + 有状态 Agent）、`packages/coding-agent`（壳）。
> 它甚至把"llama.cpp"做成独立 provider、明文要求服务端 `--jinja`——
> 和你第 1 章要撞的坑一模一样。分层不是教科书洁癖，是被工业实践反复验证的形状。

> **引经据典（反面）**｜hermes-agent（NousResearch）
> 同一仓库里也躺着反面教材：早期把主循环写在单个 `run_agent.py`（约 46 万字符），
> 后续花大力气往 `agent/` 包里拆。架构债是真的会欠的——我们第一天就分对。

## 0.3 术语与规范索引

**不要现在背**。遇到新词回这查；每条带权威出处，查得到原始定义。

### 通信与数据格式

| 术语 | 定义 | 出处 |
|---|---|---|
| **HTTP** | 应用层协议：客户端发请求（方法+地址+头+体），服务端回响应（状态码+头+体） | MDN HTTP |
| **API** | 应用编程接口；本书特指 HTTP API：约定好请求/响应格式的远程调用 | — |
| **JSON** | 文本数据格式 `{"键":"值"}`；模型间传输的一切结构化数据 | json.org |
| **SSE**（Server-Sent Events） | 服务器单向持续推送的 HTTP 流，`Content-Type: text/event-stream`；每帧 `data:` 前缀、空行分隔 | MDN Server-sent events；第 2 章手写 |
| **流式（streaming）** | 不等全部生成完，边产边发。首字延迟从"全部完成"缩到"第一个 token" | — |

### 模型与推理

| 术语 | 定义 | 出处 |
|---|---|---|
| **LLM** | 以 token 为单位生成文本的神经网络 | — |
| **token** | 模型处理文本的最小单位；中文约 1 字≈1 token、英文约 4 字符≈1 token（近似） | OpenAI token 文档 |
| **prompt** | 发给模型的全部输入（含历史与工具说明书） | — |
| **上下文窗口** | 模型一次能"看见"的 token 上限 | — |
| **量化（quantization）/ GGUF** | 权重 16bit→4bit 压缩，体积速度大降能力略降；GGUF 是 llama.cpp 的模型文件格式 | llama.cpp 文档 |
| **KV cache** | 引擎对已处理 prompt 前缀的缓存：前缀不变则免重算——长对话提速的关键，第 5 章实测 | llama.cpp 文档 |
| **temperature** | 采样随机性：0 近乎确定（实验/存证必用 0），越大越发散 | OpenAI 规范 |
| **推理（inference）** | 模型生成 token 的计算过程；"推理引擎"= 跑它的程序 | — |

### 协议关键字段（全书主角）

| 术语 | 定义 | 出处 |
|---|---|---|
| **messages** | 对话历史数组，每条 `{role, content}`；role ∈ system/user/assistant/tool | OpenAI 规范 |
| **tool_calls** | assistant 消息里的字段：模型举手"我要调这个工具"（含工具名与参数） | OpenAI 规范 function calling |
| **tool_call_id** | 调用唯一 id；工具结果消息必须带同值 id 回填，**配对不能拆** | 同上；第 3 章的核心不变量 |
| **JSON Schema** | 描述 JSON 结构的标准；工具的"说明书"，模型照着生成参数 | json-schema.org |
| **finish_reason** | 停止原因：`stop`（说完）/ `tool_calls`（要调工具）/ `length`（token 上限截断） | OpenAI 规范 |
| **usage** | token 统计：prompt_tokens / completion_tokens | OpenAI 规范 |
| **reasoning_content** | 思考模式字段：答案前的推理文本（Qwen 系命名；另有引擎叫 `reasoning`） | 各引擎扩展，第 6 章双认 |

### 工程术语

| 术语 | 定义 |
|---|---|
| **TDD / 测试先行** | 先写"期望行为"的测试（必然失败），再写实现让它通过 |
| **报文存证** | 每次请求/响应的原始字节落盘，事后可追溯可复现 |
| **故障注入** | 故意搞坏某环节，验证兜底真的兜得住 |
| **降级** | 高级路径走不通时退到保守路径（如"没收工具，逼模型直接回答"） |
| **幂等** | 同一操作重复执行结果不变——重试安全的前提 |

## 0.4 命令行最低配置（五课，每课五分钟）

**1. 目录与路径**
```
cd D:\LLM          # 进目录（Mac/Linux: cd /tmp）
cd ..              # 回上级
pwd                # 我在哪
```
> ⚠️ 全书第一坑：Windows 反斜杠 `\` 在 JSON 与多数 shell 里是转义符，多层传递
> 会被吞——`D:\LLM` 变 `D:LLM`（第 1 章有现场）。**约定：写进 JSON/代码的
> Windows 路径一律用正斜杠 `D:/LLM`**，Windows 自己认。

**2. 环境变量**
```
$env:TAGENT_MODEL = "D:/LLM/models/qwen.gguf"    # PowerShell
export TAGENT_MODEL=/path/model.gguf             # bash / Mac
```

**3. 管道与重定向**
```
curl -s http://127.0.0.1:8081/health > resp.json
type resp.json        # 看内容（Mac: cat）
```

**4. 退出码（exit code）**
```
curl -s http://127.0.0.1:9999/health; echo "exit=$?"
# connection refused → exit=7。成败永远看退出码，不看"有没有输出"——纪律 6。
```

**5. 进程与端口**
```
netstat -ano | findstr 8081      # 谁占着 8081（Mac: lsof -i :8081）
taskkill /PID 1234 /F            # 杀进程（Mac: kill 1234）
```
"端口被占用"是新手第一大报错，先会查它。

## 0.5 慢的预期：CPU 推理真实速度

全程 CPU（Qwen3.5-4B，20 核，真机实测）：

| 操作 | 速度 |
|---|---|
| 模型加载 | ~3 秒 |
| 生成 | ~12 token/秒（50 字中文回答约 4-5 秒） |
| 思考模式开启 | 可能 3-10 倍慢且不一定更好（第 6 章数据） |

慢是特性不是缺陷：它逼你写出**对每一步精打细算**的 agent——少一轮循环、
省一个 token 都是真实收益。这是本教程比"调云端 API"教程多学到的东西。
