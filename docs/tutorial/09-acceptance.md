# 第 9 章 收官：让它说"我做完了"不算数

> 本章目标：把全书的验收方式升级为**机器裁决**（完成谓词）、建立**token 级溯源**
> 与**两级复现**制度，最后是结业大考。预计 1 天。本章没有新功能——它把前面
> 八章攒下的存证变成可自动断言的资产。

---

## 9.1 问题：验收为什么不能靠"看一眼"

到目前为止你验收的方式：跑一遍、肉眼盯 stdout、觉得对。三个漏洞：

1. **LLM 自证不可信**：模型说"已完成查询"不等于查询真的发生了、参数是对的、
   结果是成功的——这话本身就是它生成的文本
2. **人眼会累**：六场景 × 每章回归，看漏一次就是一次静默退化
3. **不可复现的验收不是验收**："我上次跑是对的"在工程上等于零

对策分三层，本章逐一建立：**完成谓词**（机器裁决"做完没有"）、**溯源**
（每个 token 有据可循）、**复现口径**（什么算"再来一遍成功了"）。

## 9.2 完成谓词：任务完成由事件流事实裁决

核心立场（来自对多 agent 系统的调研，但道理通用）：**退出码 0 不算数、
模型的话不算数——完成 = 事件流里的事实满足显式断言**。

我们第 3 章起就在攒事件流（transcript），现在写断言器消费它：

```ts
// packages/core/src/predicate.ts（骨架，完全体见参考实现）
export interface PredicateResult { ok: boolean; evidence: string }
export interface TaskPredicate {
  describe(): string;
  check(events: AgentEvent[], messages: ChatMessage[]): PredicateResult;
}

/** 断言：工具被调用过，且参数深包含 spec（{"city":"北京"}） */
export function toolCalled(name: string, args?: Record<string, unknown>): TaskPredicate { /* ... */ }

/** 断言：该工具至少一次成功（信封 ok:true——调用过 ≠ 成功过） */
export function toolResultOk(name: string): TaskPredicate { /* ... */ }

/** 断言：存在终答（final 事件）且内容含关键词 */
export function finalAnswers(includes?: string): TaskPredicate { /* ... */ }

/** 组合：全部满足才通过，一条不满足即未完成 */
export function all(...preds: TaskPredicate[]): TaskPredicate { /* ... */ }
```

设计要点：

- **证据必须引用具体事件**：通过时给"get_weather 以满足 {"city":"北京"} 的参数
  被调用（id=call_abc…）"；失败时给"终答不含'晴'（实际前 120 字：…）"——
  裁决是可复核的记录，不是布尔黑箱
- **`toolResultOk` 与 `toolCalled` 分开**：这是"调用过 ≠ 成功过"的制度化——
  场景 5（火星）里调用失败但诚实说明，正确的谓词是 `finalAnswers("无法")`
  （意图达成），而不是硬要成功调用

配一个 CLI 裁决器，从 transcript 重放事件流：

```powershell
node scripts/verify-task.mjs captures/win-ac-1/transcript.jsonl ^
  "{\"all\":[{\"toolCalled\":\"get_weather\",\"args\":{\"city\":\"北京\"}},{\"toolResultOk\":\"get_weather\"},{\"finalIncludes\":\"晴\"}]}"
# 输出：✔ 任务完成（机器裁决）
#   证据: get_weather 以满足 … 的参数被调用（id=…）；至少一次成功（…）；终答存在且含"晴"（…）
```

再把六场景的谓词固化成一张表（`verify-acceptance.mjs`），从此每章回归 =
跑一遍 + 机器裁决全绿——**第 4 章纪律 6 的完全体**。

诚实边界（必须记录）：谓词断言的是**事件流事实**。如果工具真有外部副作用
（发邮件、写生产库），"事件流说成功"与"世界真的变了"仍是两回事——那是
idempotency/对账的领域，超出本书范围，但你要知道边界在哪。

## 9.3 溯源：每个 token 有据可循

存证分两个精度档，都从第 1 章就开始攒了，本章给它们正式定义：

**档一：会话存证（第 1 章的方法系统化）**
每次 LLM 通信落一个目录：`request.json`（发出的请求体）+ `response.sse`
（引擎返回的原始字节流，拼接所有帧含 keepalive）。

**档二：token 级溯源（trace）**
对 `response.sse` 做一次确定性重放（无时间戳，同输入同输出——git 友好），
产出逐 token 索引，每行：

```json
{ "seq": 42, "kind": "text", "frame": 38, "line": 75, "byte": 3417, "text": "京" }
```

四个坐标的含义：第 42 个 token（seq）来自第 38 帧（frame），该帧首行在原文件
第 75 行（line）、第 3417 字节（byte）处开始。**三方印证**：拿 trace 里任意
一行，都能回到 `response.sse` 的对应字节亲眼核实——"这个 token 引擎真的吐过"。

```ts
// trace 的断言测试（教程版的正确性证明）：
const r2 = recs[1];
const slice = SSE_BUF.subarray(r2.byte, r2.byte + 5).toString("utf8");
assert.equal(slice, "data:");    // byte 坐标指向帧起始——注意用 Buffer 定位，
                                 // 中文字符在 JS string 里 1 码元 3 字节，string.slice 会错位（真实踩坑）
```

溯源的实际用处：模型某句话"不对劲"时，你能回答"这是引擎第几帧吐的、
当轮 prompt 是什么、 KV cache 命中了多少"——**从"感觉它错了"到"定位到字节"**。

## 9.4 两级复现口径

"复现"必须先定义级别，否则永远在吵（以下是项目复盘认可的口径）：

| 级别 | 定义 | 用途 |
|---|---|---|
| **任务级** | 同一任务：agent 跑一次成功；照着存证里的请求手工重发一次（curl/手敲 prompt），任务也能完成 | 验收标准——证明流程没有隐藏魔法 |
| **字节级** | temperature=0（+关闭投机解码）下，同一请求重发，token 流逐项一致 | 实验口径——数据可信的前提 |

两个口径各自的坑（真机实录）：

- **默认温度暗坑**：两个引擎默认温度不同（一冷一热），"同请求"行为天差地别——
  实验必须显式带 temperature，抓包固定 0
- **投机解码破坏字节级复现**：MTP/投机解码在数学上分布等价，但贪心解码时
  浮点归约顺序差异会在近平局 token 上翻转——严格重放实验要关掉它
  （第 1 章启动脚本没开它，就是为此留的干净底座）

任务级复现的仪式感建议：全书学完做一次"手敲复现"——挑一个多工具任务，
按 agent 存证里的 prompt 序列手工 curl 重发，亲眼看着不走 agent 循环也能
完成任务。那一刻你对"agent 循环到底自动化了什么"的理解会具体起来。

## 9.5 结业大考（五题，每题 20 分）

全部为实践题，机器可验证的用谓词验收：

1. **换工具**：给 agent 加一个 `get_time` 工具（返回当前时间），用谓词验收
   "现在几点了"任务（`toolCalled("get_time")` + `finalAnswers` 含时间数字）
2. **算账**：用第 5 章估算器跑 10 轮对话，画一张"估算 vs 引擎 usage"误差表，
   结论写明你的平均误差与是否需要校准系数
3. **A/B 复刻**：挑一个你自己的任务集（≥5 题），复刻 6.3 的思考开关实验，
   给出你机器上的两组成功率/耗时（不许照抄教程结论）
4. **故障验收**：设计一个新故障剧本（如 `get_weather:slow` 延迟 5 秒但成功），
   验证超时策略与最终回答都对，存证齐全
5. **跨壳复用**：把你的大脑（packages/core）接到第 2 章聊天壳之外任意一个新壳
   （网页一行 fetch 也算），证明零改动——这是第 0 章架构承诺的终验

评分参考：60 分及格（功能完成）；80 分（存证齐全）；满分（每题都有一段
"翻车与修复"或"反直觉发现"的记录——因为那才是你真的动过手的证据）。

## 9.6 全书总复习：十件事

1. agent = LLM + 工具 + 循环；循环二十行，纪律八条
2. 三件套分层，大脑零依赖，壳随便换（第 0/2/8 章）
3. 协议字段是契约：配对不拆、assistant 先入档、finish_reason 分流（第 3 章）
4. 模型不可靠是常态：信封恒不抛、失败分两类、降级靠没收（第 4 章）
5. 上下文是预算：估算-双水位-前缀稳定，user 消息一个字不动（第 5 章）
6. 开关落在协议层：/no_think 是骗局，思考默认关（第 6 章）
7. 缰绳：steering 下一轮生效、取消半截不回填、守卫有限次可观测（第 6 章）
8. 弱模型的救生圈是受限解码，不是更好的 prompt（第 7 章）
9. 并行要配互斥键，事件要源序（第 7 章）
10. 验收的终点是机器裁决 + 溯源到字节 + 分级复现（本章）
