## 10.1 验收的三个层次

"跑一遍看一眼"的三个漏洞：**LLM 自证不可信**（"已完成查询"这话本身就是它
生成的文本）；**人眼会累**（六场景 × 每章回归，看漏一次就是静默退化）；
**不可复现的验收不是验收**。对策三层：谓词（机器裁决）、溯源（有据可循）、
复现口径（什么算"再来一遍成功了"）。

## 深入一层：人机边界的界定——自主性分级与打扰经济学

"哪些 agent 自己干、哪些必须人参与"的第一性判据不是技术能力，是
**错误的可逆性与可发现性**。由此得到五级自主性阶梯：

| 级 | 任务形态 | 策略 |
|---|---|---|
| L0 | 直答（无工具） | 全自动 |
| L1 | 只读工具（查询/检索） | 全自动——错误无副作用 |
| L2 | 可逆写操作（git 分支/本地文件） | 全自动 + **可回滚**（快照/分支）+ 事后可审 |
| L3 | 对外副作用（发消息/提交 PR） | 默认人审；低风险白名单自动放行 |
| L4 | 不可逆高危（删生产数据/付费/对外发布） | 硬性人审；**无人值守时默认拒绝** |

工业实践三件套（hermes/clowder/pi）：**可回滚性优先于审批**（把动作设计成
可逆，可逆就不必事前问——影子快照/worktree/会话树）；**按后果分流**
（clowder 只有效应类操作进审批，fyi/调查类自动投递；hermes 的 hardline
floor 连 --yolo 也拦住 mkfs/根删除）；**白名单学习**（批过一次的模式
持久化放行——打扰密度随信任下降）。

**"全自动 24 小时"的准入三件套**：意图可形式化（验收能写成谓词）、
过程可回滚、结果可验证——**三缺一就得人进环**。偏差的防线因此前移成
三层：system prompt 行为锚（粗）→ 开工前验收谓词（精）→ 运行期 steering
纠偏（第 7 章）。

**"该问就问"本身是能力**：好 agent 的提问结构化、低频、带默认项
（"我准备 X，除非你说不然"——proceed-by-default），只在**不可逆且不可
推断**的分叉上问；坏 agent 每步都问，等于把自主性外包给用户。

**诚实边界**：全自动系统的最大风险不是做错，是**错得很有信心**（第 4 章
模型编造天气的放大版）——所以验证侧（本章的谓词）比生成侧（放权）更值得
投资。人的角色随系统成熟度演进：执行每一步 → 定义验收与处理异常 →
设计菜单与边界（架构期决策，第 8 章能力选型）。

## 10.2 完成谓词：任务完成由事件流事实裁决

核心立场：**退出码 0 不算数、模型的话不算数——完成 = 事件流里的事实满足
显式断言**。第 3 章起攒的事件流（transcript）现在是断言器的输入：

```ts
// packages/core/src/predicate.ts（骨架；完全体见 tagent）
export interface PredicateResult { ok: boolean; evidence: string }
export interface TaskPredicate {
  describe(): string;
  check(events: AgentEvent[]): PredicateResult;
}

export function toolCalled(name: string, args?: Record<string, unknown>): TaskPredicate
//   断言：该工具被调用过，且参数深包含 spec——证据引用调用 id
export function toolResultOk(name: string): TaskPredicate
//   断言：该工具至少一次成功（信封 ok:true）
//   ——与 toolCalled 分开是"调用过 ≠ 成功过"的制度化
export function finalAnswers(includes?: string): TaskPredicate
//   断言：存在终答且含关键词
export function all(...preds: TaskPredicate[]): TaskPredicate
//   组合：一条不满足即未完成
```

两个设计要点：

- **证据必须引用具体事件**（调用 id / 结果信封片段 / 终答前 120 字）——
  裁决是可复核的记录，不是布尔黑箱
- **谓词表达意图而非形式**：火星场景的正确谓词是 `finalAnswers("无法")`
  ——诚实说明查不了就是这个场景的"完成"

CLI 裁决器从 transcript 重放：

```powershell
node scripts/verify-task.mjs captures/ac-1/transcript.jsonl ^
  "{\"all\":[{\"toolCalled\":\"get_weather\",\"args\":{\"city\":\"北京\"}},
              {\"toolResultOk\":\"get_weather\"},{\"finalIncludes\":\"晴\"}]}"
# ✔ 任务完成（机器裁决）
#   证据: get_weather 以满足 … 的参数被调用（id=…）；至少一次成功（…）；终答含"晴"（…）
```

六场景谓词固化成 `verify-acceptance.mjs`，从此回归 = 跑一遍 + 机器裁决全绿
——第 4 章纪律 6 的完全体。

> **引经据典**｜clowder-ai `docs/architecture/a2a-protocol.md`
> 多 agent 平台把这一立场推到极致：任务完成由**类型化证据**裁决（PR 的
> canonical OID、持久化 revision），原文："carrier 退出码 0、响应文本，
> 都只是 carrier 事实，不裁决 action 成功"。诚实边界也一并说清：谓词断言
> **事件流事实**——工具若真有外部副作用（发邮件），"流里说成功"与"世界
> 真的变了"仍是两回事。那是幂等与对账的领域，超出本书，但你要知道边界在哪。

## 10.3 溯源：token 级三方印证

存证两档（第 1 章起就在攒，现在正式化）：

**档一：会话存证**——每次通信一个目录：`request.json` + `response.sse`
（引擎原始字节流，含 keepalive）。

**档二：trace**——对 `response.sse` 做确定性重放（无时间戳，同输入同输出），
产出逐 token 索引：

```json
{ "seq": 42, "kind": "text", "frame": 38, "line": 75, "byte": 3417, "text": "京" }
```

第 42 个 token 来自第 38 帧，帧首行在原文件第 75 行第 3417 字节。
**三方印证**：拿 trace 任意一行回 `response.sse` 的对应字节亲眼核实。

一个必踩的实现坑（真机实录）：**byte 是 Buffer 字节偏移，不是 JS 字符串
码元偏移**——中文 1 码元 3 字节（第 2 章②的 UTF-8 知识在这里第三次回扣），
用 `string.slice` 断言必错位，必须 `Buffer.subarray`：

```ts
const r2 = recs[1];
assert.equal(SSE_BUF.subarray(r2.byte, r2.byte + 5).toString("utf8"), "data:");
```

## 10.4 两级复现口径

| 级别 | 定义 | 用途 |
|---|---|---|
| **任务级** | 同一任务：agent 跑一次成功；照存证手工重发（curl/手敲 prompt），任务也能完成 | 验收标准——证明流程无隐藏魔法 |
| **字节级** | temperature=0（+关投机解码）下同一请求重发，token 流逐项一致 | 实验口径——数据可信的前提 |

两个口径各自的坑：**默认温度暗坑**（两引擎默认温度可能不同——"同请求"
在两边是两种行为，实验必须显式 temp=0）；**投机解码破坏字节级复现**——
值得最后一节"深入一层"。

## 深入一层：投机解码为什么破坏贪心确定性

投机解码（speculative decoding，llama.cpp 的 MTP/draft 模式）原理：
小模型（草稿）一次猜 k 个 token，大模型**一次前向并行验证** k 个——接受
前缀、从首个分歧处重采样。数学上与直接用大模型**分布等价**（证明依赖
拒绝采样校正），吞吐提升 20-40%（第 1 章②的带宽账：一次权重扫描验证 k 个）。

但**贪心（T=0）下它不保证逐字节一致**，机制在浮点：验证时大模型对 k 个位置
的计算被**批在一起**（一个矩阵乘），而逐 token 生成是**单独**算——
GEMM（矩阵乘）的归约顺序随批大小变化，浮点加法不满足结合律，结果在
第 16 位有效数字上抖动。两个 token 的 logits 本来就近平局时，这个抖动
翻转 argmax——输出在"Melancholic"/"Calm"这类分叉点开岔（真机实录：同请求
在 409 字符处首次分叉，之后各自保持连贯）。

工程结论：**分布正确性 ≠ 逐字节确定性**。日常使用随便开（快 20-40%）；
严格重放/对照实验必须关。这也是第 1 章⑤"复现要固定引擎+量化+采样参数"
的完整版。

## 10.6 全书十件事

1. agent = LLM + 工具 + 循环；循环二十行，纪律八条
2. 模型只承诺文本；结构化字段是引擎后处理的礼物（第 3 章②）
3. 配对不拆、先入档、messages 唯一事实（第 3 章）
4. 失败二分法：信封恒不抛、只重试瞬时、没收优于恳求（第 4 章）
5. 上下文三笔账；前缀稳定=缓存命中=78% 的速度（第 1/6 章）
6. user 消息一个字不动；压缩先算账（第 6 章）
7. 思考是预算消费者：默认关、按需开、开就给足（第 7 章）
8. 守卫有限次可观测；半截内容绝不入档（第 7 章）
9. 弱模型的救生圈是受限解码（GBNF 在采样层锁格式），不是更好的 prompt（第 8 章）
10. 验收的终点：机器裁决 + 溯源到字节 + 分级复现（本章）
